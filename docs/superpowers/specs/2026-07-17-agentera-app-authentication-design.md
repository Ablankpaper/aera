# AgentEra APP 认证与个人空间设计

状态：2026-07-17 已逐节确认，可进入实施计划阶段前的书面审阅。

## 目标

为 AgentEra Studio 增加独立的产品账户体系和云端认证服务，使用户在启动页结束后必须完成登录，或者持有仍然有效的签名离线凭证，才能进入软件并使用本地功能。

第一阶段必须形成完整、可单独验收的账户闭环：网页注册登录、密码找回、设备管理、桌面回跳、最多五台活跃设备、七天滚动离线授权、自动创建个人空间、既有本地 Profile 认领和自助注销。

认证功能只负责产品准入、设备身份和本地空间选择。它不得替代、拦截、上传或改写 Hermes 的 Memory、USER、Skill、Profile、Curator、后台复盘和自我学习机制。

## 仓库和产品边界

本设计涉及以下独立边界：

- `Ablankpaper/aera`：AgentEra Studio 桌面客户端；本规格存放于此。
- `Ablankpaper/aera-cloud`：私有仓库，作为 AgentEra APP 的专用云端后端和网页账户中心。
- `Ablankpaper/aera-runtime`：AgentEra Runtime；第一阶段不修改其核心学习和执行逻辑。
- `bignormal/agentera-claw-api`：独立的充值与模型 API 中转网站，不是 AgentEra APP 的账户后端。

`aera-cloud` 可以与充值网站共用同一台物理服务器、PostgreSQL 进程、Redis 进程和反向代理，但必须使用独立数据库、数据库角色、Redis 凭据与命名空间、域名、Cookie、签名密钥和加密密钥。

AgentEra APP 账户和充值网站账户之间不共享 `user_id`、Token、Cookie、邮箱/手机号绑定、余额、会话或单点登录。桌面充值按钮只打开已配置的充值网页，不携带 AgentEra 身份材料；同一个人可以在充值网站另行注册多个账户。

现有 `src/main/hermes-account.ts`、`src/main/account-store.ts` 和 Remote Dashboard OAuth 属于不同兼容功能。新的 AgentEra 产品认证必须使用独立模块、存储、IPC 名称和后端配置，不得把现有 Hermes Account 当作产品登录。

## 已考虑的技术方案

### 采用：Go 模块化单体 + React/Vite

`aera-cloud` 使用一个 Go 应用承载认证 API、账户 API、后台任务和编译后的 React/Vite 账户中心。PostgreSQL 是持久化事实来源，Redis 保存验证码、短期授权状态、限流计数和临时锁。

该方案适合共享的 4 核 16 GB 服务器：运行时内存较低、部署单元少、故障面小，并且可以在业务增长后按模块拆分，而不需要在第一版引入微服务协调成本。目标应用容器预算为 0.5–1 vCPU 和 256–512 MB 内存，不包含共享 PostgreSQL 与 Redis。

### 未采用：TypeScript/Fastify + React

前后端和桌面端使用相同语言有利于共享类型，但 Node.js 服务在这台共享服务器上的常驻资源、依赖树和运行维护面更大。第一阶段的跨语言 API 契约可以通过 OpenAPI 和契约测试解决，因此不以统一语言换取额外运行成本。

### 未采用：Keycloak、Supabase 或其他完整身份平台

完整身份平台提供大量现成功能，但会引入更重的部署、升级、定制和供应商边界。当前个人维护规模只需要邮箱/手机号、密码、设备会话和桌面 OAuth，不需要先运行一套通用身份基础设施。

## 第一阶段范围

### `aera-cloud`

- 邮箱或中国大陆手机号任选其一注册、登录和找回密码。
- 登录后绑定另一种身份；一个已验证身份在 AgentEra 账户体系内只能属于一个用户。
- 可选昵称，不设置独立用户名。
- 浏览器账户中心、设备列表、身份绑定、密码修改和自助注销。
- Authorization Code + PKCE 桌面授权、短期 Access Token、滚动 Refresh Token 和签名离线凭证。
- 最多五台活跃设备；超限时必须移除旧设备后才能完成新设备授权。
- 注册事务中自动创建一个个人空间。
- 邮件、短信、验证码清理、过期会话清理和注销冷静期任务。
- 健康检查、数据库迁移、审计日志、备份恢复和受限运维命令。

### AgentEra Studio

- 启动页之后的产品登录门禁。
- 调用系统默认浏览器完成登录、注册和找回密码。
- 本机随机回环端口、PKCE、`state` 校验和一次性授权码交换。
- 平台安全存储、联网续签、七天离线模式、设备失效和系统时间回拨检测。
- 账户切换、退出登录、本地 Profile 绑定和既有数据认领。
- 保持充值按钮为独立网页跳转，不增加 SSO 或余额同步。

### 明确不包含

- 会话、文件、`MEMORY.md`、`USER.md`、Curator 状态或本地学习技能的云同步。
- 独立端到端加密备份。
- 工作区、组织、企业角色与策略。
- 官方 Agent 的云端安装、发布、灰度和回滚。
- 完整运营管理后台。
- 充值网站账户、余额或 API Key 的自动关联。
- 对 Hermes Runtime 核心、自我学习或 Profile 数据布局的重写。

## 云端组件

`aera-cloud` 保持模块化单体。每个模块只能通过明确接口访问其他模块，不允许用共享全局状态绕过边界。

### HTTP 与网页层

同一个 HTTPS Origin 提供 React/Vite 账户中心和版本化 JSON API。网页层负责注册、登录、找回密码、绑定身份、设备管理、注销和浏览器授权确认；静态资源编译后嵌入或随 Go 二进制一起部署。

### 身份与凭证模块

身份模块负责邮箱/手机号规范化、唯一性、验证和绑定。凭证模块只处理 Argon2id 密码哈希、密码修改和重置；任何模块都不能读取明文密码。

### OAuth 与会话模块

OAuth 模块验证固定桌面 `client_id`、精确回环 Redirect URI、PKCE challenge、随机 `state` 和设备公钥。会话模块负责 Access Token、Refresh Token family、轮换、重放检测、注销和设备撤销。

### 设备与离线授权模块

设备模块维护安装实例、设备公钥、显示名称、平台、最后活动和撤销状态。离线授权模块使用独立 Ed25519 密钥签发七天凭证，并记录签发审计；服务端不能在设备完全离线时即时收回已签发凭证。

### 个人空间模块

个人空间在注册事务内创建，只提供稳定的 `personal_space_id` 和所有权边界。第一阶段不在个人空间内存储 Hermes 私有运行数据。

### 通知和后台任务模块

邮件和短信通过可替换的 Provider 接口发送。生产环境禁止使用会把验证码写入普通日志的假 Provider。后台任务首版运行在同一 Go 进程中，使用数据库或 Redis lease 防止多实例重复执行；确有负载后再拆分 Worker。

### 运维入口

首版不建设公开管理后台。禁用账户、撤销会话、查看脱敏审计和执行恢复操作通过服务器 CLI 或仅内网可达的受限运维接口完成，并记录操作者与结果。

## 核心数据模型

所有主键由服务端生成，为无业务含义的稳定 UUID。时间统一存 UTC。数据库约束是身份唯一性和关系完整性的最终防线。

### `users`

保存用户主体、可选昵称、状态、创建时间、密码安全版本和注销时间。状态至少包括 `active`、`pending_deletion` 和 `disabled`。

### `identities`

保存 `email` 或 `phone` 类型、加密值、HMAC 查询索引、验证时间和所属用户。`(kind, lookup_hmac)` 建立唯一约束。邮箱和手机号均不得作为其他表的主键或跨系统关联键。

### `password_credentials`

保存 Argon2id 哈希、参数版本和最后修改时间。密码长度允许 10–128 个字符，不强制无意义的特殊字符组合，并允许密码管理器生成的长口令。

### `personal_spaces`

保存个人空间 ID、所属用户、显示名称和状态。注册创建用户、首个身份、密码凭证和个人空间必须在同一个 PostgreSQL 事务内完成。

### `devices`

保存用户、安装实例 ID、设备公钥、设备名称、平台、应用版本、最后活动、撤销时间和状态。只有未撤销设备计入五台上限。

### `sessions`

保存设备会话、Refresh Token family、当前 Token 哈希、到期时间、轮换关系、撤销原因和重放检测结果。数据库不保存 Refresh Token 明文。

### `verification_challenges`

保存目的、目标身份 HMAC、使用独立服务端密钥生成的验证码 HMAC、到期时间、失败次数和消费状态。六位验证码熵较低，不能用可离线穷举的普通 SHA 哈希替代 keyed HMAC；验证码本身不写入日志或数据库。

### `oauth_requests` 与 `authorization_codes`

保存固定客户端、精确 Redirect URI、PKCE challenge、设备公钥摘要、短期到期时间和一次性消费状态。授权码只保存哈希，有效期两分钟，成功交换或失败消费后不能再次使用。

### `offline_entitlement_issuances`

保存离线凭证 `jti`、用户、设备、签发时间、到期时间和密钥 ID，用于审计和联网后的撤销判断。离线凭证本体由客户端安全保存。

### `audit_events`

保存事件类型、主体、设备、对象 ID、结果、原因、时间和必要的请求元数据。不得复制密码、验证码、Token、完整邮箱/手机号或 Hermes 私有内容。

### `legal_acceptances`

保存用户接受的服务条款与隐私政策类型、版本和时间。生产注册只接受服务器当前公布的版本；文档正文由版本化静态内容管理，不复制进每条接受记录。

## 注册和账户生命周期

### 注册

用户在浏览器选择邮箱或手机号，获取六位验证码并设置密码。验证码五分钟有效，六十秒后可重发，连续输错五次后作废。服务按身份、IP 和设备进行可配置限流，只在异常频率下要求人机验证。

验证成功并接受当前服务条款与隐私政策后，服务在一个事务内创建用户、已验证身份、密码凭证、接受记录和默认个人空间。昵称可留空并在账户中心修改。

### 绑定另一身份

已登录用户必须重新输入当前密码，并验证新的邮箱或手机号。新身份若已属于其他 AgentEra 用户则拒绝绑定。用户不得解绑最后一个可登录身份。

### 修改和找回密码

普通修改密码保留当前设备会话并撤销其他设备会话。找回密码通过已绑定身份验证码完成，成功后撤销全部设备会话、Refresh Token family 和后续联网时可识别的离线授权。

### 五台设备上限

新设备完成身份验证后，如果账户已有五台活跃设备，浏览器显示设备列表并要求用户先撤销一台。服务在事务或互斥锁内再次检查数量，避免并发登录突破上限。

### 退出登录

退出登录撤销当前设备会话，把设备标记为非活跃并清除本机 AgentEra Token、设备授权和离线凭证；该设备不再计入五台上限，但保留脱敏审计。以后重新登录时可以在重新检查五台上限后复用同一安装实例和设备公钥。退出不会删除、移动或重写本地 Profile。切换账户先阻止新任务、安全停止当前任务，再卸载当前本地空间。

### 自助注销

用户在网页账户中心重新输入密码并通过已绑定身份验证码后发起注销。服务立即把账户设为 `pending_deletion`，撤销在线会话和设备授权，并开始七天冷静期。

冷静期内只有身份恢复流程可重新激活账户，普通 OAuth 授权不能进入软件。冷静期结束后删除或匿名化云端身份与个人空间元数据，移除身份唯一索引，使同一邮箱或手机号可以重新注册；保留的安全审计必须去标识化且不含 Hermes 私有数据。

注销不会删除本机 Hermes 会话、Memory、文件或学习成果。注销页面必须先提醒用户导出或单独删除本地数据。已完全离线的其他设备最迟在当前七天凭证到期后停止准入，这是签名离线模式的明确限制。

## 桌面授权流程

### 启动状态机

现有 `App.tsx` 在 Splash 期间计算安装与连接检查结果。实施时保留该预检，但把结果保存为 `postAuthTarget`，不直接进入 `welcome`、`setup` 或 `main`。

固定顺序为：

1. 显示 AgentEra Studio 启动页并执行不读取用户内容的 Runtime/连接预检。
2. 主进程检查 AgentEra 在线会话和签名离线凭证。
3. 有效时检查本地 Profile 绑定；Runtime 已安装时先完成选择或认领，再进入 `setup` 或 `main`。
4. 无效时进入 AgentEra 登录门禁；即使 Runtime 尚未安装，也必须先登录再进入安装页。
5. 全新未安装设备在认证后可以进入 `welcome/installing`，但安装完成后必须先创建并绑定空 Profile，才能进入 `setup` 或 `main`。
6. 任何能够启动用户任务、读取会话或展示 Memory 的界面都要求认证和 Profile 绑定同时完成。

远程和 SSH Runtime 模式同样受 AgentEra 产品门禁约束。预检可以启动必要连接探测，但在确定 AgentEra 用户前不得挂载、同步或展示用户 Profile 内容。

AgentEra 产品 Token 不转发给 Remote/SSH Runtime，也不替代远端自身的连接认证。远端连接配置和凭证在桌面侧按 AgentEra 本地所有者绑定；另一个 AgentEra 用户不能继承前一用户的远端连接上下文。

### Authorization Code + PKCE

1. 桌面主进程生成 PKCE verifier/challenge、不可预测 `state` 和随机回环端口；同时从平台安全存储读取安装级设备 Ed25519 密钥对，首次使用时才生成。
2. 主进程在 `127.0.0.1` 上启动只接受一次回调的短时 HTTP listener。
3. 系统浏览器打开 `aera-cloud` 的固定桌面授权端点，携带固定 `client_id`、精确 Redirect URI、challenge、state 和设备公钥材料。
4. 用户在网页完成登录、注册或找回密码。密码和验证码从不经过 Electron Renderer 或主进程。
5. 服务向回环地址返回一次性短期授权码和原始 `state`，不在 URL 中放 Access Token、Refresh Token 或离线凭证。
6. 主进程验证来源路径和 `state`，使用授权码、verifier 和设备私钥证明换取会话。
7. 服务原子消费授权码，登记设备，签发 Token 和离线凭证。
8. 浏览器显示“登录成功，可以返回 AgentEra Studio”，桌面窗口恢复到前台。

Redirect URI 只允许 `http://127.0.0.1:PORT/agentera/oauth/callback` 这一固定结构，其中 `PORT` 由操作系统动态分配并由本次授权请求精确登记。生产授权服务自身必须使用 HTTPS。自定义 URL Scheme、嵌入式 WebView 和设备码轮询不在第一阶段使用。

用户关闭浏览器、授权码超时或端口冲突时，桌面保持登录门禁并允许生成一组全新的参数重试。切换账户必须请求重新选择或重新验证网页账户，不能因系统浏览器已有 Cookie 而静默进入上一个账户。

## Token、设备绑定和离线模式

### Access Token

Access Token 为 Ed25519 签名、带 `kid` 的最小化 JWT，有效期十五分钟。Claims 只包含签发者、受众、用户 ID、会话 ID、设备 ID、个人空间 ID 和时间，不包含邮箱、手机号或 Hermes 内容。Token 只存在 Electron 主进程内存中，Renderer 不可读取。

签名 JWT 不是撤销状态的唯一判断依据。云端 API 验证签名和时效后，还必须通过撤销缓存及其 PostgreSQL 事实来源确认会话、设备和账户仍然有效，因此联网设备撤销不需要等待十五分钟自然过期。

### Refresh Token

Refresh Token 是至少 256 bit 的不透明随机值，有效期三十天。每次成功刷新均轮换并续期；数据库只保存哈希和 family 关系。已被替换的 Token 再次出现时，服务撤销该设备整个 family 并记录重放事件。

### 离线凭证

离线凭证由独立 Ed25519 密钥签名，包含用户、设备、安装实例、个人空间、签发时间、到期时间、策略版本和 `jti`，有效期七天。每次成功联网验证后重新获得完整七天期限。

桌面在启动、恢复联网和正常会话刷新时验证服务端状态并更新凭证。离线凭证绑定设备公钥，复制到另一台设备不能使用。桌面持有内置的验证公钥集合，通过 `kid` 支持平滑轮换。

平台安全存储使用 Electron `safeStorage` 或等价平台抽象，由 macOS Keychain、Windows DPAPI 和可用的 Linux Secret Service 提供保护。Refresh Token、设备私钥和离线凭证保存在主进程专用的产品认证存储中；安全存储不可用时拒绝落盘，不允许明文降级。

### 离线行为

有效凭证允许进入软件并使用本地功能。AgentEra 云同步、官方版本发现、工作区和企业功能暂停。模型全部通过 API 调用，因此模型 Endpoint 不可达时无法推理；如果模型 Endpoint 可达而 AgentEra 控制面不可达，Hermes 对话和本地自我学习仍可继续。

七天到期后，桌面在启动或开始新用户任务前返回登录门禁。已经运行的任务先安全落盘，不删除或重置本地状态。系统保存最后可信服务端时间和单调时钟锚点；发现明显时钟回拨时要求联网验证，避免无限延长授权。

设备撤销、账户冻结或注销在联网时立即阻止新任务和云功能。设备完全离线时最迟在当前离线凭证到期后失效。

## 本地 Profile 绑定和既有数据迁移

AgentEra 产品会话存储位于应用级安全目录，不能放在某个 Hermes Profile 内，因为登录发生在 Profile 选择之前。独立的本地绑定记录至少包含 `cloud_user_id`、`personal_space_id`、`runtime_profile_id`、安装实例和绑定时间，但不包含 Memory 内容。

第一阶段把 Runtime Profile contract 的最小身份元组具体化为：`tenant_id = personal_space_id`、`owner_scope = USER`、`owner_id = cloud_user_id`、稳定的本地 `installation_id` 和 `runtime_profile_id`。即使官方 Agent Installation 尚未实现，这些 ID 也必须先稳定生成，后续只能扩展而不能根据可编辑名称重新推断。

### 首次登录

如果当前安装没有有意义的既有 Profile 数据，桌面创建或选择一个空 Profile 并直接绑定。

如果检测到既有会话、Memory、USER、技能、文件或 Curator 状态，桌面在登录成功后显示一次性选择：

- “使用现有本地数据”：把当前物理 Profile 原地绑定到已登录用户和个人空间，不移动、复制、重写、哈希上传或云同步任何内容。
- “创建全新空间”：创建物理隔离的空 Profile；既有数据原地保留为未绑定数据，并可从设置中的本地数据认领入口选择。

检测只读取本地存在性和必要元数据，不把内容发送到云端。新 Profile 必须从空模板创建，不能调用可能复制凭证、Memory、USER、技能或 Curator 状态的通用 Hermes clone 路径。

### 隔离规则

一个物理 Profile 只能绑定一个 AgentEra 所有者。普通退出登录不会解除绑定；另一个 AgentEra 用户不能挂载已经绑定的 Profile。跨账户转移必须作为未来独立的导出/导入和双方验证流程，不属于普通账户切换。

这里的隔离目标是防止 AgentEra 应用内的账户串用，并依赖操作系统账户权限保护本地文件。第一阶段不把整个 Hermes Profile 加密，因此不能承诺抵御拥有同一操作系统账户文件权限或 root/管理员权限的本地攻击者；端到端加密备份也不会改变这一明确威胁边界。

注销云端账户同样不会自动重新分配本地 Profile。用户必须在注销前导出或删除本地数据；离线到期、服务故障和 Token 丢失均不得删除 Profile。

这些规则继续服从 `docs/agentera-runtime-profile-contract.md`：数据库 owner 字段不能替代物理 `HERMES_HOME` 隔离。

## 敏感数据和认证安全

- 密码使用带参数版本的 Argon2id 哈希。
- 邮箱和手机号使用每记录随机 nonce 的 AES-256-GCM 加密。
- 查询和唯一性使用独立 HMAC-SHA-256 密钥生成的规范化索引。
- 加密密钥、HMAC 密钥、JWT 密钥和离线签名密钥相互独立，并带 `key_id` 支持轮换。
- 密钥只通过生产 Secret 注入，不能进入 Git、镜像层、普通日志或数据库备份。
- 密钥轮换时支持新旧 `key_id` 验证和受控重建 HMAC 索引；离线保存恢复副本。
- 网页 Cookie 使用 `HttpOnly`、`Secure`、恰当的 `SameSite` 和 CSRF 防护。
- 授权端点执行 CSP、Origin、固定客户端、精确 Redirect URI、PKCE、state 和一次性消费校验。
- 验证码、登录、找回密码和授权交换按身份、IP、设备与时间窗限流。
- 日志自动遮盖身份、验证码、授权码和 Token，不记录 Hermes 私有内容。
- PostgreSQL 备份加密，并定期验证恢复，而不是只验证备份文件存在。

## 故障处理

认证默认安全关闭，但有效签名离线凭证是明确的本地例外。

- 网络中断且离线凭证有效：进入本地模式，现有本地任务继续，后台指数退避重试。
- 网络恢复：自动验证、续签并恢复允许的云功能，无需重启。
- 离线凭证过期：返回登录门禁，不提供隐藏绕过开关。
- PostgreSQL 或 Redis 不可用：暂停新注册、登录、验证码和会话变更；有效离线用户仍可本地使用。
- 邮件或短信失败：不创建半完成账户，不把 Provider 故障伪装成验证码错误。
- `state`、PKCE、设备签名或 Redirect URI 不匹配：拒绝请求并记录脱敏安全审计。
- 浏览器关闭、回调超时或端口冲突：清理临时 listener 和 OAuth request，允许完整重试。
- 注册、Token 交换、刷新、注销和设备撤销使用事务、唯一约束或幂等键处理重复提交。
- 明确撤销或冻结：立即阻止新任务，安全停止当前任务，再返回登录门禁。
- 任何认证异常都不得删除、替换、合并或上传 Hermes Memory、USER、会话、文件、技能和 Curator 状态。

PostgreSQL 是持久化事实来源。Redis 故障不能触发无验证码、无限流或忽略撤销的宽松认证回退。

## 部署边界

### 开发环境

本地开发使用独立 PostgreSQL 数据库、Redis namespace、测试邮件/短信接收器和本地 `aera-cloud`。桌面通过运行时或构建环境配置读取授权服务地址，不在代码中写死 IP 或域名。

### 私有测试环境

服务可以部署到现有大陆服务器，但服务器主 IP 只通过 VPN、SSH Tunnel 或严格 IP 白名单提供给开发人员。裸公网 IP 不定义为生产环境，也不通过普通 HTTP 传输密码、验证码或 Token。

### 生产环境

生产环境使用已备案域名下的独立 HTTPS Origin，例如由 `AGENTERA_CLOUD_PUBLIC_URL` 配置的账户域名。域名备案、可信 TLS、真实邮件/短信 Provider、隐私政策和服务条款就绪后才开放公网注册。

一个 Go 应用容器承载 API、网页静态资源和首版后台任务；PostgreSQL 与 Redis 可复用服务器现有进程，但使用独立数据库/角色和独立 ACL/命名空间。反向代理只把账户域名路由到 `aera-cloud`，不得与充值站 Cookie 或路径混用。

测试与生产使用不同数据库、Redis 凭据、加密密钥和签名密钥。迁移必须向前可恢复，部署前执行加密备份，失败时回滚应用版本而不是自动逆向破坏性 Schema。

## 后续路线

本认证阶段是现有 Hermes 兼容架构中的“认证与个人空间”交付，但根据已确认的产品优先级提前到 Agent 配置/版本云同步之前。该顺序调整是安全的，因为第一阶段只建立身份、设备和本地 Profile 绑定，不启用官方 Agent 安装或任何私有数据同步。

后续按以下顺序分别设计、计划和验收：

2. Agent Definition、配置与不可变版本同步，不上传用户运行数据。
3. 用户主动开启的客户端加密备份，服务器只保存密文。
4. 工作区、组织、企业角色、策略与审计。
5. 官方 Agent 审核、脱敏、灰度、回滚和演化发布管线。

每一项都需要独立规格。后续阶段不能以方便同步为由重新引入整个 `MEMORY.md`、会话、文件或未提升技能的自动上传。

- PostgreSQL/Redis/邮件/短信故障与幂等重试。

### 浏览器端到端测试

- 邮箱和手机号注册、登录、找回密码和绑定另一身份。
- 五台设备管理、超限处理、密码修改和自助注销/恢复。
- OAuth 成功、取消、过期、重复回调和恶意 Redirect URI。

## 验收条件

- 启动页后必须先通过在线会话或有效七天离线凭证，才能进入任何本地、远程或 SSH 使用路径。
- 用户可用邮箱或手机号完成网页注册、登录和找回密码，并自动获得个人空间。
- 浏览器回跳只携带一次性授权码；桌面验证 PKCE、state 和设备证明后才保存会话。
- 每账户最多五台活跃设备；并发登录不能突破限制。
- 每次成功联网验证后离线期限滚动为七天。
- 退出、设备撤销、密码重置、注销和服务故障均不删除本地 Profile。
- 既有本地数据只能在用户明确选择后原地绑定；不会被复制或上传。
- 邮箱和手机号以“加密值 + HMAC 查询索引”存储。
- AgentEra APP 与充值网站账户、Token、Cookie、余额和用户 ID 完全独立。
- Hermes Memory、USER、Skill、Profile、Curator、后台复盘和自我学习机制保持原样并通过回归门禁。
- 第一阶段不包含 Memory/会话云同步、加密备份、企业空间或官方 Agent 发布。
